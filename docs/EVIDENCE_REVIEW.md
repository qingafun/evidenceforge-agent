# 证据审阅

每条证据都有单独的审阅记录。系统区分“资料是否支持当前报告”和“资料中的事实是否已独立核实”：完成前者会显示已审阅，不会自动把后者标为已核验。

## 自动审阅与人工复核

模型驱动模式在撰写报告后增加一个证据审阅步骤。Agent 对照原问题、报告和每条原文片段，判断资料是否相关、能否支持引用它的说法，并给出简短理由。每条证据必须返回一条有效结果；遗漏、重复、未知编号和无效格式都会导致任务失败，不能凭报告生成成功推断证据已审阅。

| 显示 | 含义 |
| --- | --- |
| 待审阅 | 这份报告与这条证据还没有匹配的审阅记录 |
| Agent 已审阅 | 模型已检查该条证据，并保存结论、理由、模型名称和时间 |
| 人工已审阅 | 用户已提交对这条证据的复核结论与理由 |
| 规则已检查 | 离线模式仅检查原文和引用结构，没有调用模型进行语义审阅 |

“已审阅”表示执行过审阅，不等于结论一定为通过。审阅结论另行显示为“支持引用”“有疑问”“不支持引用”或“未用于报告”。被报告引用的证据，如果自动审阅认为内容不支持、存在疑问或不相关，整份报告无法通过验收。系统最多修订一次，再次未通过时保留草稿。

人工复核可以在研究完成、失败或取消且已有报告时进行。在证据卡片中查看原文、来源与自动审阅理由，选择自己的判断并填写理由后保存。人工意见保留自动结果，不会删除它；每次修改都会记入执行轨迹。人工认为被引用的证据有疑问或不支持时，界面和下载报告会提示需要处理，并将结果按草稿展示。人工确认某条证据也不能替代其他未通过的答案完整性或质量检查。

## 历史记录与版本

记录与原问题、报告正文和证据内容共同绑定。修改报告、改换来源或生成不同的内容后，旧的判断不会自动沿用。页面提交的版本与服务端不一致时，保存会被拒绝，需要重新查看当前材料后复核。

升级前的历史报告没有逐条审阅记录，因此仍显示待审阅。可以在历史证据卡片中人工复核，也可以新建研究重新走完整自动流程。程序不会把旧报告批量改成“已审阅”。新记录保存在原任务数据库中，重启后保留；下载的 Markdown 会附上证据审阅表。

## 审阅的边界

自动审阅使用配置的同一模型服务，以独立步骤检查报告所引用的资料片段；没有额外的第二模型服务配置。联网证据来自搜索接口返回的片段，审阅步骤不会自动打开网页全文、认证发布者身份或寻找多个独立来源。因此，“Agent 已审阅”不代表“官方网站已确认”或“已独立事实核验”。

离线模式不消耗模型 API，仅记录规则检查；需要语义判断时可以人工复核，或配置模型后新建模型驱动研究。模型驱动模式会增加一次批量证据审阅请求，修订时会再次审阅，使用当前研究的 Token 预算与请求超时设置。
